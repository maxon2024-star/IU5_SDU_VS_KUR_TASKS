## 1. Введение и теоретическая база

Данная лабораторная работа открывает цикл непрерывного проекта по разработке собственного микропроцессора (Soft-core). Работа выполняется исключительно в симуляторе, таком как ModelSim, Icarus Verilog или Vivado. Такой подход позволяет нам сфокусироваться на архитектурных решениях и написании качественных тестбенчей, не ограничиваясь аппаратными лимитами реальных ПЛИС.

**Основная цель:** Создание памяти процессора на уровне регистров и организация внутренних шин данных.

Теоретической базой для выполнения работы служат материалы Модуля 1, Лекции 7-8, охватывающие принципы работы регистров, шин и мультиплексоров. 

**Краткая справка:**
Операционный автомат (Datapath) процессора выполняет всю "черновую" работу по обработке данных. Его фундаментом является **Регистровый файл (Register File, RF)**. Это сверхбыстрая память внутри процессора, состоящая из набора регистров общего назначения (РОН). Чтобы процессор мог за один такт выполнить операцию (например, сложить два числа и сохранить результат), регистровый файл должен уметь одновременно выдавать значения из двух разных регистров и записывать новые данные в третий. Выбор конкретных регистров для чтения осуществляется с помощью аппаратных мультиплексоров.

## 2. Генерация индивидуального варианта (Google Colab)

Каждый студент выполняет уникальное задание. Скопируйте приведенный ниже скрипт на Python в ячейку Google Colab (или запустите локально), подставьте свои данные и получите архитектурные параметры вашего регистрового файла.

```python
import hashlib

def generate_lab1_variant(year, group, variant):
    """
    Генератор вариантов для Лабораторной №1.
    """
    
    seed_string = f"{year}-{group}-{variant}"

    hash_object = hashlib.md5(seed_string.encode())
    hash_int = int(hash_object.hexdigest(), 16)
    
    # Наборы архитектурных параметров
    bit_widths = [8, 16, 32] 
    reg_counts = [8, 16] # Базовое требование: 8 или 16 регистров
    reset_types = [
        "Синхронный сброс (Synchronous Reset)", 
        "Асинхронный сброс (Asynchronous Reset)"
    ]
    r0_behaviors = [
        "Обычный регистр (чтение и запись разрешены)", 
        "Hardwired Zero (Регистр 0 всегда равен 0, запись игнорируется)"
    ]
    
    # Выбор параметров с помощью остатка от деления
    width = bit_widths[hash_int % len(bit_widths)]
    count = reg_counts[(hash_int // 10) % len(reg_counts)]
    reset = reset_types[(hash_int // 100) % len(reset_types)]
    r0 = r0_behaviors[(hash_int // 1000) % len(r0_behaviors)]
    
    # Вывод ТЗ
    print("="*50)
    print(f"ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ: Группа {group}, Вариант {variant} ({year} год)")
    print("="*50)
    print(f"1. Разрядность шины данных (DATA_WIDTH): {width} бит")
    print(f"2. Количество регистров в файле:           {count}")
    print(f"3. Тип сигнала сброса (RST):               {reset}")
    print(f"4. Поведение нулевого регистра (R0):       {r0}")
    print("="*50)
    print("Используйте эти параметры (параметризацию Verilog) при написании кода!")

# === ВВЕДИТЕ СВОИ ДАННЫЕ СЮДА ===
generate_lab1_variant(year=2026, group="ИУ5-41Б", variant=15)
```

## 3. Описание задания и базовые примеры кода

Вам необходимо спроектировать структурный базис операционного автомата. 

**Пошаговые задачи:**
1. Написать на языке аппаратного описания Verilog модуль регистрового файла (Register File), содержащий 8 или 16 регистров общего назначения, в зависимости от вашего варианта.

3. Организовать внутренние шины данных, используя мультиплексоры для маршрутизации сигналов.
4. Написать проверочный модуль (тестбенч) для проверки независимости процессов записи и чтения.

> **Важно по параметризации:** Обратите внимание, что параметры `DATA_WIDTH` и `ADDR_WIDTH` задаются при инстанцировании (вызове) модуля через конструкцию `#(...)`. Ваш код не должен содержать жестко заданных чисел (например, `[15:0]`). Он должен автоматически адаптироваться под любые параметры, переданные из тестбенча.

### Базовый шаблон модуля `register_file.v`

Ниже представлен упрощенный пример. **Ваша задача — доработать его под параметры, выданные скриптом.**

```verilog
module register_file #(
    parameter DATA_WIDTH = 16, // Разрядность данных (из варианта)
    parameter ADDR_WIDTH = 3   // Разрядность адреса (3 для 8 регистров, 4 для 16)
)(
    input  wire                  clk,
    input  wire                  rst,        // Учитывайте тип сброса из варианта!
    input  wire                  we,         // Write Enable (разрешение записи)
    
    input  wire [ADDR_WIDTH-1:0] read_addr1, // Адрес для 1-го порта чтения
    input  wire [ADDR_WIDTH-1:0] read_addr2, // Адрес для 2-го порта чтения
    input  wire [ADDR_WIDTH-1:0] write_addr, // Адрес для порта записи
    
    input  wire [DATA_WIDTH-1:0] write_data, // Данные для записи
    
    output wire [DATA_WIDTH-1:0] read_data1, // Данные 1-го порта чтения
    output wire [DATA_WIDTH-1:0] read_data2  // Данные 2-го порта чтения
);

    // Объявление двумерного массива для имитации набора регистров
    reg [DATA_WIDTH-1:0] registers [(1<<ADDR_WIDTH)-1:0];
    
    integer i;

    // Блок записи (пример с СИНХРОННЫМ сбросом)
    always @(posedge clk) begin
        if (rst) begin
            // Сброс всех регистров
            for (i = 0; i < (1<<ADDR_WIDTH); i = i + 1) begin
                registers[i] <= {DATA_WIDTH{1'b0}};
            end
        end else if (we) begin
            // ЗАДАНИЕ: Если в варианте "Hardwired Zero", добавьте проверку write_addr != 0
            registers[write_addr] <= write_data;
        end
    end

    // Блок чтения (комбинаторная логика, работающая как мультиплексор)
    // TODO: Если в варианте "Hardwired Zero", R0 при чтении всегда должен отдавать 0
    assign read_data1 = registers[read_addr1];
    assign read_data2 = registers[read_addr2];

endmodule
```

## 4. Критерии приемки и контрольные вопросы

### Критерии успешной сдачи 
* **Синтаксис:** Код регистрового файла и тестбенча компилируется в симуляторе без ошибок и предупреждений.
* **Параметризация:** Разрядность данных и количество регистров заданы через параметры `parameter`, а не "захардкожены".
* **Логика работы:** Временные диаграммы (Waveforms) доказывают, что запись по порту А не мешает чтению по портам B и C в тот же такт.
* **Специфика варианта:** Реализован правильный тип сброса (синхронный/асинхронный) и правильное поведение нулевого регистра.
* **Полнота покрытия:** Тестбенч осуществляет запись во все регистры, сброс системы и чтение случайных регистров.
