## 1. Введение и теоретическая база

Мы уже создали "мышцы" (Datapath) и "мозг" (Control Unit) нашего процессора. Но сейчас он страдает "амнезией" — ему негде хранить саму программу и большие массивы данных.

В этой работе мы реализуем **Гарвардскую архитектуру** подсистемы памяти. Это значит, что у нас будут два физически разделенных модуля:

1. **Instruction ROM (Память команд):** Хранит код программы. Процессор может только *читать* из нее инструкции.
2. **Data RAM (Память данных):** Хранит переменные и массивы. Процессор может и *читать*, и *записывать* туда данные.

Также мы добавим ключевой элемент — **Program Counter (Счетчик команд, PC)**, который указывает, по какому адресу в ROM лежит следующая инструкция.

**Цель работы:** Подключение памяти, создание счетчика команд и реализация инструкций работы с памятью (Load/Store).

### Ликбез: Прямая и Косвенная адресация

Для работы с RAM мы добавим инструкции **LOAD** (чтение из памяти в регистр) и **STORE** (запись из регистра в память).

* **Прямая адресация:** Адрес ячейки жестко закодирован в самой инструкции (например, `LOAD R1, [0x1A]`).
* **Косвенная регистровая адресация:** Адрес ячейки лежит в другом регистре (например, `LOAD R1, [R2]`). Это позволяет делать циклы по массивам, просто увеличивая значение `R2`.

## 3. Описание задания и базовые примеры кода

### 3.1 Счетчик команд (`pc.v`)

Это регистр, который каждый такт делает `+1` (указывая на следующую команду), либо загружает новый адрес, если мы выполняем операцию перехода (Jump).

```verilog
module pc #(
    parameter ADDR_WIDTH = 8
)(
    input  wire                  clk,
    input  wire                  rst,
    input  wire                  pc_write, // 1 = Разрешение изменения PC
    input  wire                  jump_en,  // 1 = Сигнал перехода (Jump)
    input  wire [ADDR_WIDTH-1:0] jump_addr,// Куда переходим
    
    output reg  [ADDR_WIDTH-1:0] pc_out
);

    always @(posedge clk) begin
        if (rst) begin
            pc_out <= {ADDR_WIDTH{1'b0}}; // При сбросе начинаем с нулевого адреса
        end else if (pc_write) begin
            if (jump_en) pc_out <= jump_addr;
            else         pc_out <= pc_out + 1;
        end
    end
endmodule

```

### 3.2 Память команд (ROM) и Память данных (RAM)

**Модуль `rom.v` (Только чтение, асинхронно):**

```verilog
module instruction_rom #(
    parameter DATA_WIDTH = 16,
    parameter ADDR_WIDTH = 8
)(
    input  wire [ADDR_WIDTH-1:0] addr,
    output wire [DATA_WIDTH-1:0] instruction
);
    reg [DATA_WIDTH-1:0] rom_array [0:(1<<ADDR_WIDTH)-1];

    initial begin
        // Загружаем прошивку. Функция зависит от вашего варианта!
        $readmemb("program.bin", rom_array); 
    end

    assign instruction = rom_array[addr];
endmodule

```

**Модуль `ram.v` (Чтение и Запись):**
Запись *всегда* должна быть синхронной (по фронту `clk`), чтобы не повредить данные в соседних ячейках!

```verilog
module data_ram #(
    parameter DATA_WIDTH = 16,
    parameter ADDR_WIDTH = 8
)(
    input  wire                  clk,
    input  wire                  we,     // 1 = Идет запись
    input  wire [ADDR_WIDTH-1:0] addr,
    input  wire [DATA_WIDTH-1:0] data_in,
    output wire [DATA_WIDTH-1:0] data_out
);
    reg [DATA_WIDTH-1:0] ram_array [0:(1<<ADDR_WIDTH)-1];

    always @(posedge clk) begin
        if (we) ram_array[addr] <= data_in; // Синхронная запись
    end

    assign data_out = ram_array[addr];      // Асинхронное чтение
endmodule

```

### 3.3 Прошивка программы (`program.bin`,`program.hex`)

Создайте файл `program.bin` в папке симуляции (там же, откуда будете запускать симулятор).

> **Использование подчеркиваний `_`:` `**
> Читать сплошной поток из 16 нулей и единиц (типа `0100000100000011`) — это боль. К счастью, **Verilog позволяет использовать символ нижнего подчеркивания `_` в бинарных и hex-файлах** для визуального разделения! Симулятор просто проигнорирует их при чтении. Используйте это, чтобы отделить OpCode от адресов регистров.

**Пример `program.bin`:**

```text
// Формат инструкции: [OpCode_4bit]_[DestReg_4bit]_[SrcReg1_4bit]_[SrcReg2_4bit]
// -----------------------------------------------------------------------------
0001_0001_0000_1010  // LDI R1, 10   (Положить число 10 в R1)
0001_0010_0000_0101  // LDI R2, 5    (Положить число 5 в R2)
0010_0011_0001_0010  // ADD R3, R1, R2 (Сложить R1 и R2, результат в R3)
1100_0000_0011_0000  // STORE R3, [0x00] (Сохранить результат из R3 в ячейку памяти 0)
1111_0000_0000_0000  // HALT (Остановка процессора / Бесконечный цикл на месте)

```

Для чтения файла `.hex`в Verilog вместо `$readmemb` (binary) используется функция **`$readmemh`** (hexadecimal).

Каждые 4 бита (нули и единицы) превращаются в 1 символ (от `0` до `F`). Поскольку ширина нашей шины данных 16 бит, каждая инструкция будет состоять ровно из **4 шестнадцатеричных цифр**.

Вот точно такая же программа, переведенная в формат `.hex`:

```text
// Файл: program.hex
// Читается в Verilog функцией: $readmemh("program.hex", rom_array);
// -----------------------------------------------------------------

110A  // LDI R1, 10   (OpCode 1, Dest 1, Константа 0x0A)
1205  // LDI R2, 5    (OpCode 1, Dest 2, Константа 0x05)
2312  // ADD R3, R1, R2 (OpCode 2, Dest 3, Src1 1, Src2 2)
C030  // STORE R3, [0x00] (OpCode C, Src 3, Адрес 0x00)
F000  // HALT (Остановка процессора)

```

### Что нужно изменить в коде (в модуле `rom.v`):

Если вы используете этот файл, убедитесь, что в блоке `initial` стоит правильная буква `h` на конце:

```verilog
    initial begin
        // Буква 'h' означает Hexadecimal (шестнадцатеричный)
        $readmemh("program.hex", rom_array); 
    end

```

> В `.hex` файлах вы тоже можете использовать нижние подчеркивания для удобства, если хотите отделить, например, старший байт от младшего!
> Строка `11_0A` или даже `1_1_0_A` будет прочитана симулятором абсолютно так же, как `110A`.

### 3.4 Системный тестбенч (`system_tb.v`)

Вам необходимо создать модуль верхнего уровня (например, `cpu_top.v`), внутри которого проводами будут соединены PC, ROM, RAM, Control Unit и Datapath.

Тестбенч для такого модуля выглядит максимально лаконично. Мы не управляем процессором — **мы просто подаем на него питание и тактовый генератор, а дальше он всё делает сам, читая `program.bin`.**

```verilog
`timescale 1ns / 1ps

module system_tb;

    // Глобальные сигналы
    reg clk;
    reg rst;

    // Инстанцирование вашего собранного процессора
    cpu_top dut (
        .clk(clk),
        .rst(rst)
    );

    // Генерация тактового сигнала (период 10 нс)
    always #5 clk = ~clk;

    initial begin
        $dumpfile("system.vcd");
        $dumpvars(0, system_tb);

        // 1. Включаем питание, процессор в состоянии сброса
        clk = 0; 
        rst = 1;
        
        // 2. Ждем пару тактов и отпускаем сброс (Reset)
        #15 rst = 0;
        $display("Система запущена. Процессор начал выборку инструкций из ROM.");

        // 3. Ждем достаточное количество времени, чтобы программа из program.bin выполнилась
        // (Например, 1000 нс = 100 тактов)
        #1000;
        
        // 4. Остановка симуляции
        $display("Симуляция завершена.");
        $finish;
    end
endmodule

```
