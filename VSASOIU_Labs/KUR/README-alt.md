# Курсовая работа по дисциплине «Вычислительные средства АСОИУ»

**Тема:** Проектирование, верификация и реализация процессорного ядра с расширяемой архитектурой системы команд на языке Verilog

## 1. Цель работы

Получение практических навыков современного проектирования цифровых устройств (RTL Design), освоение языка описания аппаратуры Verilog, методов автоматизированной верификации логики и синтеза для программируемых логических интегральных схем. Закрепление навыков разработки низкоуровневого программного обеспечения, создания инструментальной цепочки и архитектурной оптимизации под специфические вычислительные задачи.

## 2. Основное задание

Разработать функциональную модель специализированного процессорного ядра, обладающего собственной расширяемой системой команд (ISA), и реализовать его на целевой платформе (ПЛИС или детальная симуляция).

**Важное ограничение:** 

Для описания аппаратуры (RTL) используется исключительно язык Verilog. Сторонние языки (Python, C++, Bash) разрешены только для написания скриптов, ассемблеров, генераторов тестов и анализаторов.

**Двухуровневая система выполнения:**
- Часть 1 (Базовая): Выполнение этапов 1–4 + ручная подготовка машинного кода для этапа 5. Позволяет получить оценку 3 (удовлетворительно).
- Часть 2 (Расширенная): Выполнение всех требований Части 1 + разработка собственного ассемблера, реализация кастомных инструкций и автоматизированное профилирование. Позволяет получить оценки 4–5 (хорошо / отлично).

## 3. Этапы выполнения работы

### Этап 1: Разработка архитектуры и расширяемой системы команд (ISA Design)

**Задача:** Спроектировать собственную упрощенную систему команд на базе подмножества RISC-V, адаптированную под вычислительный сценарий.

**Требования:**
- Определить базовый формат команды (поля opcode, регистры, immediate-значения). Архитектура должна быть совместима с принципами RISC-V (фиксированная длина инструкций, разделение регистров и памяти, явное указание регистров назначения).
- Определить архитектуру регистрового файла (количество регистров, разрядность, поведение регистра x0, тип сброса).
- Реализовать базовый набор команд: арифметика (ADD, SUB), логика (AND, OR, XOR), работа с памятью (LOAD, STORE), управление потоком (JUMP, BEQ).
- Для Части 2 (Оценки 4–5): Спроектировать 1–2 кастомные инструкции, ускоряющие решение индивидуальной задачи (например, аппаратное умножение-накопление, быстрое вычисление контрольной суммы, специфичный сдвиг или операция насыщения). Документировать их поведение, коды операций и влияние на тракт данных.

**Результат:** Документ «Описание архитектуры (ISA Manual)».

### Этап 2: Проектирование на языке HDL (RTL Design)

**Задача:** Описать аппаратную реализацию процессора на языке Verilog.

**Требования:**
- Код должен быть модульным. Обязательные модули: ALU, Register_File, Control_Unit (конечный автомат или микропрограммное управление), Program_Counter, Memory_Top, CPU_Core.
- Использование синхронной логики (тактирование, сброс) для всех элементов хранения состояния.
- Код должен быть параметризован, снабжен комментариями и соответствовать стандартам стиля (snake_case, явные объявления портов, отсутствие нежелательных защелок/latch).
- Для Части 2 (Оценки 4–5): Реализовать аппаратную поддержку кастомных инструкций, спроектированных на Этапе 1 (модификация ALU и Control_Unit, добавление необходимых мультиплексоров или расширителей сигналов).

**Результат:** Исходный код проекта (файлы .v).

### Этап 3: Верификация и симуляция (Verification)

**Задача:** Доказать корректность работы устройства до этапа синтеза.

**Требования:**
- Написать тестовое окружение (Testbench) с автоматической генерацией clk и rst.
- Реализовать сценарий проверки: загрузка тестовой программы в память -> автономный запуск процессора -> проверка результатов в регистрах/памяти.
- Предоставить временные диаграммы (waveforms), подтверждающие прохождение тестов и корректность машинного цикла.
- Для Части 2 (Оценки 4–5): Добавить в тестбенч автоматическое сравнение конечного состояния процессора с эталонными значениями, генерируемыми скриптом на Python/C++.

**Результат:** Файл тестбенча, лог симуляции, скриншоты временных диаграмм.

### Этап 4: Синтез и реализация (Synthesis & Implementation)

**Задача:** Оценить физические параметры проекта.

**Требования:**
- Выполнить синтез проекта в среде разработки для ПЛИС (Xilinx Vivado, Intel Quartus или Yosys).
- Проанализировать отчет об использовании ресурсов (LUT, Flip-Flops, Block RAM).
- Определить максимальную рабочую частоту (Fmax) и критические пути.
- Для Части 2 (Оценки 4–5): Провести сравнительный анализ ресурсов и быстродействия между базовой версией ядра и версией с кастомными инструкциями. Оценить аппаратную стоимость ускорения.

**Результат:** Отчеты синтеза, сведения о занимаемых ресурсах и быстродействии.

### Этап 5: Программно-аппаратная интеграция и инструментальная цепочка (Advanced)

**Задача:** Написать программу для созданного процессора, решающую вычислительную задачу по индивидуальному варианту, и обеспечить её транслирование в машинный код.

**Для Части 1 (Оценка 3):**
- Составить машинный код для решения задачи варианта.
- Продемонстрировать корректное выполнение программы на спроектированном ядре в симуляторе.

**Для Части 2 (Оценки 4–5):**
- Разработать собственный ассемблер (скрипт на Python/C++), который парсит текстовый файл, а на выходе генерирует бинарный/шестнадцатеричный файл прошивки, совместимый с системными функциями загрузки памяти.
- Ассемблер должен поддерживать: псевдоинструкции (MOV, NOP, относительные переходы), расчет смещений для ветвлений, трансляцию кастомных инструкций из Этапа 1.
- Написать на разработанном ассемблере программу решения задачи по варианту.
- Реализовать автоматизированное профилирование: скрипт должен запускать симуляцию, извлекать такты выполнения, подсчитывать метрики (CPI, количество инструкций, время работы) и выводить сравнительный отчет.

**Результат:** Исходный код ассемблера, текст программы на ассемблере, скомпилированный бинарный файл, логи автоматической верификации и профилирования.

## 4. Требования к отчету

Отчет должен содержать:
1. Титульный лист.
2. Описание разработанной системы команд (ISA Manual), включая форматы команд и описание кастомных инструкций (для Части 2).
3. Схема архитектуры процессора (блок-схема взаимосвязи модулей).
4. Листинги ключевых модулей на HDL (с комментариями).
5. Описание методики тестирования и примеры тестовых векторов.
6. Временные диаграммы работы ключевых узлов.
7. Отчет о синтезе (занимаемые ресурсы, частота, сравнение базовой и расширенной версий для Части 2).
8. Для Части 2: Исходный код ассемблера, описание формата входных/выходных данных, текст программы для варианта, результаты автоматического профилирования.
9. Выводы о проделанной работе и возможных путях оптимизации (архитектурных, программных или инструментальных).

## 5. Инструментарий

*   **Языки:** Verilog – для RTL-кода, Python 3.x / C++ - для написания ассемблера, генераторов тестов.
*   **САПР:** Xilinx Vivado (WebPACK), Intel Quartus (Prime Lite), или открытые инструменты (Icarus Verilog + GTKWave, Yosys).
*   **Контроль версий:** Git (обязательно, наличие репозитория с историей коммитов).

**Принцип формирования архитектуры:** Получив вариант, студент анализирует ограничения алгоритма (разрядность данных, требуемые математические операции, тип адресации, объём RAM). На основе этого анализа на Этапе 1 проектируется архитектура и ISA, включающая необходимые кастомные инструкции. Этапы 2–4 реализуют ядро под эту задачу. На Этапе 5 (Часть 2) пишется ассемблер, транслирующий бенчмарк под полученную ISA, и проводится автоматизированная проверка. Такая схема гарантирует, что проектирование процессора будет прикладным и ориентированным на конкретную вычислительную задачу, соответствуя современным практикам разработки Domain-Specific Architectures (DSA).
