# Лабораторная работа №2: Разработка АЛУ и формирование тракта данных (Datapath)

## 1. Введение и теоретическая база

В первой лабораторной работе мы подготовили память процессора — Регистровый файл (Register File). Однако сам по себе он лишь хранит данные. Для того чтобы процессор мог выполнять вычисления, нам необходимо Арифметико-логическое устройство (АЛУ) и система связей между ними. 

Данная лабораторная работа посвящена интеграции операционного автомата (ОА) и АЛУ для создания полноценного тракта данных (Datapath). Поскольку готового АЛУ у нас пока нет, вы разработаете его с нуля, а затем объедините с регистровым файлом из первой лабораторной.

Теоретической базой для выполнения работы служат материалы Модуля 1, Лекции 4 и 8 (Взаимодействие устройств, форматы команд).

**Краткая справка:**
* **АЛУ (ALU):** Это чисто комбинаторная схема (без тактового сигнала и памяти), которая принимает два операнда, код операции (OpCode) и выдает результат вычисления.
* **Регистр флагов:** Триггеры, которые сохраняют признаки результата последней операции (например, равенство нулю, переполнение).
* **Datapath:** Это "кровеносная система" процессора. Мы соединим выходы чтения регистрового файла со входами АЛУ, а выход АЛУ заведем обратно на вход записи регистрового файла.

### Структурная схема (Datapath)

```text
               +----------------------------------+
               |          datapath.v              |
               |                                  |
   write_addr  |   +--------------------------+   |
 ------------->|   |      register_file       |   |
   read_addr1  |   |                          |   |
 ------------->|   | read_data1    read_data2 |   |
   read_addr2  |   +------|------------|------+   |
 ------------->|          |            |          |
               |   A_bus  |            | B_bus    |

 ------------->|   |           ALU            |-----> flags (Z, C, O, S)

               +----------------|-----------------+
```

### 3.1 Шаблон АЛУ (`alu.v`)

АЛУ описывается комбинаторной логикой (без тактового сигнала `clk`).

```verilog
module alu #(
    parameter DATA_WIDTH = 16
)(
    input  wire [DATA_WIDTH-1:0] a,
    input  wire [DATA_WIDTH-1:0] b,
    input  wire [2:0]            alu_ctrl, // Код операции
    
    output reg  [DATA_WIDTH-1:0] result,
    output wire                  flag_z,   // Zero
    output reg                   flag_c    // Carry (пример)
);

    // Коды операций (лучше вынести в параметры (localparam))
    localparam ALU_ADD = 3'b000;
    localparam ALU_SUB = 3'b001;
    localparam ALU_AND = 3'b010;
    localparam ALU_OR  = 3'b011;
    // Добавьте свои коды из варианта...

    always @(*) begin
        // Инициализация по умолчанию (чтобы избежать защелок/latch)
        result = {DATA_WIDTH{1'b0}};
        flag_c = 1'b0;

        case (alu_ctrl)
            ALU_ADD: {flag_c, result} = a + b; // Сложение с захватом бита переноса
            ALU_SUB: result = a - b;
            ALU_AND: result = a & b;
            ALU_OR:  result = a | b;
            // ВАША ЗАДАЧА: Реализовать остальные операции
            default: result = {DATA_WIDTH{1'b0}};
        endcase
    end

    // Флаг нуля вычисляется всегда просто: если результат равен 0
    assign flag_z = (result == {DATA_WIDTH{1'b0}});

endmodule
```

### 3.2 Шаблон Datapath (`datapath.v`)

Модуль верхнего уровня объединяет RF и ALU.

```verilog
module datapath #(
    parameter DATA_WIDTH = 16,
    parameter ADDR_WIDTH = 3
)(
    input  wire                  clk,
    input  wire                  rst,
    input  wire                  we,         // Разрешение записи в RF
    input  wire [ADDR_WIDTH-1:0] read_addr1,
    input  wire [ADDR_WIDTH-1:0] read_addr2,
    input  wire [ADDR_WIDTH-1:0] write_addr,
    input  wire [2:0]            alu_ctrl,   // Управление АЛУ
    
    // Выходы для проверки в тестбенче
    output wire [DATA_WIDTH-1:0] alu_result_out,
    output wire                  flag_z
);

    // Внутренние шины (провода)
    wire [DATA_WIDTH-1:0] rf_data1;
    wire [DATA_WIDTH-1:0] rf_data2;
    wire [DATA_WIDTH-1:0] alu_result_wire;

    // Инстанцирование регистрового файла (из Лабы 1)
    register_file #(
        .DATA_WIDTH(DATA_WIDTH),
        .ADDR_WIDTH(ADDR_WIDTH)
    ) rf_inst (
        .clk(clk),
        .rst(rst),
        .we(we),
        .read_addr1(read_addr1),
        .read_addr2(read_addr2),
        .write_addr(write_addr),
        .write_data(alu_result_wire), // <-- Результат из АЛУ идет на запись!
        .read_data1(rf_data1),        // --> Операнд А для АЛУ
        .read_data2(rf_data2)         // --> Операнд В для АЛУ
    );

    // Инстанцирование АЛУ
    alu #(
        .DATA_WIDTH(DATA_WIDTH)
    ) alu_inst (
        .a(rf_data1),                 // Подключаем выход 1 RF
        .b(rf_data2),                 // Подключаем выход 2 RF
        .alu_ctrl(alu_ctrl),
        .result(alu_result_wire),     // Результат вычислений
        .flag_z(flag_z)
    );

    // Вывод результата наружу для отладки
    assign alu_result_out = alu_result_wire;

endmodule
```

### 3.3 Ручной тестбенч (`datapath_tb.v`)

### Контрольные вопросы к защите
1. Почему модуль АЛУ описан комбинаторно (через `always @(*)`), а Регистровый Файл — синхронно (через `always @(posedge clk)`)? 
2. Что такое защелка (Latch)? Как конструкция `default` в блоке `case` (или инициализация значений в начале `always`) спасает ваше АЛУ от генерации защелок при синтезе?
3. Как математически вычисляется флаг переполнения (Overflow) при сложении двух знаковых чисел? Чем он отличается от флага переноса (Carry)?
4. Объясните механизм обратной связи (Feedback loop) в тракте данных. На каком этапе тактового импульса результат с выхода АЛУ физически сохраняется в регистровом файле?
5. Что произойдет, если в инструкции `R1 = R1 + R2` операнд и место записи совпадают (Read-Modify-Write)? Возникнет ли гонка сигналов в нашем Datapath?

> Совет по флагам: 
> Флаг `Sign (S)` — это всегда просто старший значащий бит (MSB) вашего результата.
> Флаг `Overflow (O)` возникает при сложении чисел одинакового знака, когда результат меняет знак (например, положительное + положительное = отрицательное). В Verilog для этого удобно использовать логические операторы над старшими битами операндов и результата!
