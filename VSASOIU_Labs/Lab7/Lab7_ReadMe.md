# Лабораторная работа №7: Иерархия памяти и кэш прямого отображения (Direct Mapped Cache)

## 1. Введение и теоретическая база

В Лабораторной работе №6 мы создали конвейер, предполагая, что инструкция считывается из ROM за один такт. На практике мы сталкиваемся с проблемой, известной как **«Стена памяти» (Memory Wall)**: процессоры развиваются (и наращивают частоту) гораздо быстрее, чем микросхемы динамической памяти (DRAM/Flash). Доступ к основной памяти может занимать 10, 50 или даже 100 тактов. Если бы процессор ждал память каждый раз, вся польза от конвейера сошла бы на нет.

Решением является иерархия памяти. Мы встраиваем между процессором и основной памятью **кэш-память (Cache)** — крошечный, но сверхбыстрый массив памяти (SRAM), работающий на частоте процессора. Он хранит копии наиболее часто используемых данных.

Кэш работает благодаря двум принципам локальности:

1. **Временная локальность (Temporal Locality):** Если процессор обратился к ячейке памяти (например, к переменной в цикле), высока вероятность, что он скоро обратится к ней снова.
2. **Пространственная локальность (Spatial Locality):** Если процессор выполнил инструкцию по адресу `X`, скорее всего, следующей он запросит инструкцию по адресу `X+1`.

**Цель работы:** Проектирование кэша инструкций прямого отображения (Direct Mapped Instruction Cache) и интеграция его в конвейерный процессор.

### Ликбез: Как кэш понимает, что в нем лежит? (Direct Mapped Cache)

В кэше прямого отображения каждая ячейка из медленной памяти может быть скопирована только в **одну строго определенную** строку кэша. Для этого адрес, который запрашивает процессор, аппаратно "разрезается" на 3 части (справа налево):

1. **Offset (Смещение):** Указывает на конкретное слово *внутри* кэш-линии. Если ваша кэш-линия хранит только 1 слово, Offset = 0 бит. Если 2 слова — Offset занимает 1 бит (выбирает левое или правое слово).
2. **Index (Индекс):** Номер строки в самом кэше. Если в кэше 8 строк, под Index выделяется 3 бита ($2^3 = 8$). По этому индексу мы мгновенно обращаемся к нужной ячейке кэша.
3. **Tag (Тег):** Уникальный "паспорт" данных. Поскольку в строку №3 могут попасть данные из разных мест основной памяти (например, с адресов `0x03`, `0x13`, `0x23`), Тег сохраняется внутри кэша и показывает, *чей именно* кусок памяти сейчас там лежит.
4. **Valid Bit (Бит валидности):** Дополнительный служебный бит. При включении процессора в кэше лежит случайный мусор. Valid = 0 означает "строка пустая". Когда мы скачиваем реальные данные из ROM, мы ставим Valid = 1.

**Формула попадания (Cache Hit):** `Hit = Valid && (Tag_in_Cache == Tag_from_CPU)`.

### 3.1 Структурная схема (System with Cache)

```text
  +------+  cpu_addr  +---------------+   mem_addr  +-------------------+
  |      |----------->|               |------------>|                   |
  | CPU  |            |     Cache     |             | Slow Memory (ROM) |
  | (PC) |<-----------|  Controller   |<------------|   (Задержка!)     |
  |      |  cpu_inst  |               |   mem_data  |                   |
  +------+            +---------------+             +-------------------+
      ^                       | 
      |                       | stall (Заморозка конвейера на время Miss)
      +-----------------------+

```

### 3.2 Шаблон Кэш-контроллера (`icache.v`)

В данном примере показан базовый шаблон для кэша, где **1 строка = 1 слово (Offset = 0)**.
*(Если по варианту у вас 2 слова на строку, вам придется добавить бит Offset и скачивать из ROM два слова подряд!)*

```verilog
module instruction_cache #(
    parameter ADDR_WIDTH = 8,
    parameter DATA_WIDTH = 16,
    parameter INDEX_BITS = 3 // 2^3 = 8 строк кэша
)(
    input  wire                   clk,
    input  wire                   rst,
    
    // Интерфейс с процессором (CPU)
    input  wire [ADDR_WIDTH-1:0]  cpu_addr,
    output wire [DATA_WIDTH-1:0]  cpu_data,
    output wire                   cpu_stall, // 1 = Заморозить конвейер процессора
    
    // Интерфейс с медленной памятью (Main Memory)
    output wire [ADDR_WIDTH-1:0]  mem_addr,
    input  wire [DATA_WIDTH-1:0]  mem_data,
    input  wire                   mem_ready  // 1 = Память отдала данные
);

    localparam TAG_BITS = ADDR_WIDTH - INDEX_BITS;
    localparam CACHE_DEPTH = 1 << INDEX_BITS;

    // Массивы кэш-памяти (SRAM внутри кэша)
    reg [DATA_WIDTH-1:0] cache_data  [0:CACHE_DEPTH-1];
    reg [TAG_BITS-1:0]   cache_tag   [0:CACHE_DEPTH-1];
    reg                  cache_valid [0:CACHE_DEPTH-1];

    // Разбор адреса, пришедшего от процессора
    wire [TAG_BITS-1:0]   addr_tag   = cpu_addr[ADDR_WIDTH-1 : INDEX_BITS];
    wire [INDEX_BITS-1:0] addr_index = cpu_addr[INDEX_BITS-1 : 0];

    // Логика обнаружения попадания (Cache Hit)
    wire hit = cache_valid[addr_index] && (cache_tag[addr_index] == addr_tag);

    // Если нет попадания (Miss), мы должны остановить процессор!
    assign cpu_stall = !hit;
    
    // Если Hit - отдаем данные. Иначе - отдаем мусор (процессор все равно на паузе)
    assign cpu_data = hit ? cache_data[addr_index] : {DATA_WIDTH{1'bx}};

    // Запрашиваем данные из основной памяти
    assign mem_addr = cpu_addr;

    // Обновление кэша при Cache Miss (когда память наконец-то ответила)
    integer i;
    always @(posedge clk) begin
        if (rst) begin
            for (i = 0; i < CACHE_DEPTH; i = i + 1) begin
                cache_valid[i] <= 1'b0; // При сбросе кэш пуст
            end
        end else if (!hit && mem_ready) begin
            // Основная память прислала данные! Сохраняем их в кэш.
            cache_valid[addr_index] <= 1'b1;
            cache_tag[addr_index]   <= addr_tag;
            cache_data[addr_index]  <= mem_data;
        end
    end

endmodule

```

### 3.3 Имитация медленной памяти (`slow_rom.v`)

Стандартный `rom.v` отвечал мгновенно. Мы пишем обертку, которая искусственно задерживает выдачу данных на $N$ тактов.

```verilog
module slow_rom #(
    parameter ADDR_WIDTH = 8,
    parameter DATA_WIDTH = 16,
    parameter MISS_PENALTY = 5 // Задержка из вашего варианта!
)(
    input  wire                   clk,
    input  wire [ADDR_WIDTH-1:0]  addr,
    
    output reg  [DATA_WIDTH-1:0]  data_out,
    output reg                    ready // Поднимается в 1, когда данные готовы
);

    reg [DATA_WIDTH-1:0] rom_array [0:(1<<ADDR_WIDTH)-1];
    initial $readmemb("program.bin", rom_array);

    reg [3:0] wait_counter = 0;
    reg [ADDR_WIDTH-1:0] last_addr = {ADDR_WIDTH{1'b1}};

    always @(posedge clk) begin
        if (addr != last_addr) begin
            // Процессор запросил новый адрес! Начинаем отсчет.
            wait_counter <= 1;
            ready <= 0;
            last_addr <= addr;
        end else if (wait_counter < MISS_PENALTY) begin
            // Ждем...
            wait_counter <= wait_counter + 1;
            ready <= 0;
        end else begin
            // Время вышло! Выдаем данные.
            ready <= 1;
            data_out <= rom_array[addr];
        end
    end

endmodule

```

### 3.4 Интеграция в конвейер

В Лабораторной №6 вы делали Hazard Unit, который выдавал сигнал `stall` при конфликте данных.
Теперь у вас появился **второй источник заморозки** — кэш-память (`cpu_stall` от `icache`).

Сигнал приостановки счетчика команд (PC) и регистра (IF/ID) должен быть логическим "ИЛИ" (OR) этих двух событий:
`assign global_stall = data_hazard_stall || cache_miss_stall;`

### 4.3 Как читать результаты симуляции?

Что вы должны увидеть в консоли терминала при запуске:

**Итерация 1 (Первый проход цикла - Обучение кэша):**

* Процессор запрашивает адрес `0000`. Кэш пуст. `Hit = 0`, `Stall = 1`.
* Конвейер замирает. Мы ждем 5 тактов (Miss Penalty).
* На 6-й такт `ROM Ready = 1`. Инструкция попадает в кэш. Снимается `Stall`.
* Процессор запрашивает `0001`. Снова `Hit = 0`, `Stall = 1`. Снова ждем 5 тактов.

**Итерация 2 (Второй проход цикла - Магия кэша):**

* Процессор прыгает обратно и запрашивает адрес `0002` (инструкция SUB).
* **Магия!** `Hit = 1`, `Stall = 0`. Инструкция отдается за 1 такт. Медленная ROM даже не просыпается.
* Цикл выполняется на максимальной скорости конвейера!
