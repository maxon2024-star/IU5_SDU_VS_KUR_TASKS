В этой памяти каждая строка (микрокоманда) содержит готовый набор нулей и единиц для управляющих сигналов ОА и адрес следующей микрокоманды.

### Естественная vs Принудительная адресация микрокоманд

В вашем генераторе вариантов вам попадется один из двух типов архитектуры МПУУ:

1. **Естественная адресация (Natural Addressing):**
   * **Как работает:** По умолчанию счетчик микрокоманд (uPC) просто делает `+1` каждый такт (как в обычном процессоре). Если нужно сделать цикл или ветвление, используется специальный бит `Jump Enable`.
   * **Плюсы:** Экономит память (микрокоманда получается «уже», так как поле адреса перехода нужно не всегда).
   * **Минусы:** Более сложная логика счетчика (нужно выбирать между `+1` и адресом перехода).

2. **Принудительная адресация (Forced Addressing):**
   * **Как работает:** В *каждой* микрокоманде жестко зашит адрес *следующей* микрокоманды. Операции `+1` не существует вообще.
   * **Плюсы:** Очень простая аппаратная логика (адрес из ROM просто заводится обратно на вход регистра uPC через мультиплексор).
   * **Минусы:** Память расходуется неэффективно (микрокоманда становится «шире» на количество бит адреса).

### 3.1 Структурная схема (Microprogrammed Control Unit)

```text
               +---------------------------------------+
               |         Microprogrammed CU            |
               |                                       |
  Условия ---->|  +---------+         +-------------+  |-----> we_rf
 (Zero, Sign)  |  |         | адрес   |             |  |-----> alu_ctrl
               |  |  uPC    |-------->|   uROM      |  |
  OpCode ----->|  |  Logic  |         | (Микрокод)  |  |-----> (другие сигналы)
               |  |         |<--------|             |  |
    clk ------>|  +---------+ обратн. +-------------+  |
    rst ------>|                 связь                 |
               +---------------------------------------+
```

### 3.2 Расшифровка формата микрокоманды (Bit-mapping)

В базовом примере ниже используется **10-битная** микрокоманда при естественной адресации. Разберем, за что отвечает каждый бит:

| Бит(ы) | Название поля | Описание |
| :--- | :--- | :--- |
| **[9]** | `uJump` | Разрешение перехода. `0` = идем к следующей строке (uPC+1). `1` = прыгаем на адрес из поля `Jump_Addr`. |
| **[8:5]**| `Jump_Addr` | 4-битный адрес, куда перейдет uPC, если `uJump == 1`. Если `uJump == 0`, эти биты игнорируются. |
| **[4]** | `we_rf` | Write Enable для регистрового файла (1 = разрешить запись в этом такте). |
| **[3:1]**| `alu_ctrl` | 3-битный код операции для АЛУ (например, `000` = ADD, `001` = SUB). |
| **[0]** | `Cond_Jump` | Тип прыжка. `0` = безусловный (прыгаем всегда, если `uJump=1`). `1` = условный (прыгаем, *только* если флаг `Zero` из АЛУ равен 1). |

> **Внимание:** В вашем варианте разрядность и назначение полей могут отличаться в зависимости от ТЗ! 

### 3.3 Шаблон МПУУ (`micro_cu.v`)

```verilog
module micro_cu #(
    parameter UROM_WIDTH = 10,  // Ширина микрокоманды
    parameter UROM_DEPTH = 16,  // Количество микрокоманд (16 строк)
    parameter UADDR_WIDTH = 4   // Разрядность адреса uPC (2^4 = 16)
)(
    input  wire                   clk,
    input  wire                   rst,
    input  wire [UADDR_WIDTH-1:0] opcode_addr, // Стартовый адрес инструкции
    input  wire                   flag_z,      // Флаг нуля из АЛУ (для условий)
    
    // Управляющие выходы для Datapath
    output wire                   we_rf,
    output wire [2:0]             alu_ctrl
);

    // 1. Память микрокоманд (Microcode ROM)
    reg [UROM_WIDTH-1:0] urom [0:UROM_DEPTH-1];
    
    // Инициализация памяти (загрузка микрокода из файла)
    initial begin
        $readmemb("microcode.bin", urom);
    end

    // 2. Счетчик микрокоманд (uPC)
    reg [UADDR_WIDTH-1:0] upc;
    
    // Чтение текущей микрокоманды (асинхронно)
    wire [UROM_WIDTH-1:0] current_uinst = urom[upc];
    
    // Расшифровка полей микрокоманды
    wire                   ujump      = current_uinst[9];
    wire [UADDR_WIDTH-1:0] jump_addr  = current_uinst[8:5];
    assign                 we_rf      = current_uinst[4];
    assign                 alu_ctrl   = current_uinst[3:1];
    wire                   cond_jump  = current_uinst[0]; 

    // 3. Логика счетчика микрокоманд (Sequencer)
    always @(posedge clk) begin
        if (rst) begin
            upc <= 0; // Адрес стадии Fetch
        end else begin
            if (ujump) begin
                // Безусловный или условный переход
                if (!cond_jump || (cond_jump && flag_z)) begin
                    upc <= jump_addr;
                end else begin
                    upc <= upc + 1;
                end
            end else begin
                // Естественная адресация (инкремент)
                upc <= upc + 1;
            end
        end
    end

endmodule
```

### 3.4 Написание микрокода (`microcode.bin`)

Создайте текстовый файл `microcode.bin` в папке, откуда вы запускаете симуляцию. В этот файл мы запишем "прошивку" для нашей памяти микрокоманд (uROM). Функция `$readmemb` в Verilog умеет читать этот файл при старте. 

> **Совет:** Verilog игнорирует символ нижнего подчеркивания `_` в числах. Мы будем использовать его для визуального разделения полей микрокоманды, чтобы не запутаться в сплошном потоке нулей и единиц.

#### Детальный разбор: Пишем микропрограмму для инструкции SWAP

Инструкция **SWAP R1, R2** меняет значения двух регистров местами. Чтобы не использовать третью переменную (временный регистр памяти), мы применяем математический трюк с операцией XOR (Исключающее ИЛИ). Он выполняется за 3 такта процессора:
1. `R1 = R1 ^ R2` (Такт 1)
2. `R2 = R1 ^ R2` (Такт 2)
3. `R1 = R1 ^ R2` (Такт 3)

*(Примечание: выбор того, в какой именно регистр R1 или R2 идет запись, обеспечивает декодер команд, поэтому в самом микрокоде мы указываем только общие сигналы: "Записать результат" и "Сделать XOR").*

Допустим, код операции XOR в вашем АЛУ — это `011`. А выполнение нашей инструкции SWAP по архитектуре начинается с адреса `0100` (это 4 в десятичной системе). 

Давайте соберем 10-битную микрокоманду для **каждого** такта.

**Такт 1 и 2 (Обычное выполнение):**
Нам нужно сделать XOR, записать результат в регистр и просто перейти к следующей микрокоманде (uPC + 1).

| uJump (1 бит) | Jump_Addr (4 бита) | we_rf (1 бит) | alu_ctrl (3 бита) | Cond_Jump (1 бит) |
| :---: | :---: | :---: | :---: | :---: |
| **0** | **0000** | **1** | **011** | **0** |
| Прыжок НЕ нужен | Неважно (игнорируется) | Разрешаем запись | Код операции XOR | Условий нет |

**Итог для 1 и 2 такта:** `0_0000_1_011_0`

**Такт 3 (Завершение инструкции):**
Нам нужно сделать последний XOR, записать результат, а затем **вернуться в начало** (на нулевой адрес), чтобы процессор мог начать цикл Fetch (выборки) для следующей инструкции.

| uJump (1 бит) | Jump_Addr (4 бита) | we_rf (1 бит) | alu_ctrl (3 бита) | Cond_Jump (1 бит) |
| :---: | :---: | :---: | :---: | :---: |
| **1** | **0000** | **1** | **011** | **0** |
| Прыжок НУЖЕН | Прыгаем на адрес 0 (Fetch) | Разрешаем запись | Код операции XOR | Условий нет |

**Итог для 3 такта:** `1_0000_1_011_0`

#### Как должен выглядеть итоговый файл `microcode.bin`

Каждая строка в файле соответствует адресу в памяти uROM (строка 1 = адрес 0000, строка 2 = адрес 0001 и т.д.). Вы можете писать комментарии прямо в файле, используя `//`.

```text
// =================================================================================
// Формат: ujump_1bit | jump_addr_4bit | we_rf_1bit | alu_ctrl_3bit | cond_jump_1bit
// =================================================================================

// Адрес 0000: Стадия Fetch (Выборка)
// В полноценном процессоре здесь был бы прыжок на адрес, зависящий от OpCode.
// Пока поставим заглушку: безусловный прыжок на начало нашей команды SWAP (0100)
1_0100_0_000_0  

// Адрес 0001: Пусто
0_0000_0_000_0
// Адрес 0010: Пусто
0_0000_0_000_0
// Адрес 0011: Пусто
0_0000_0_000_0

// =================================================================================
// Начало микропрограммы SWAP (Адрес 0100)
// =================================================================================

// Адрес 0100 (Такт 1) : R1 = R1 ^ R2 (Перехода нет, идем на следующую строку)
0_0000_1_011_0

// Адрес 0101 (Такт 2) : R2 = R1 ^ R2 (Перехода нет, идем на следующую строку)
0_0000_1_011_0

// Адрес 0110 (Такт 3) : R1 = R1 ^ R2 (Конец SWAP! Заставляем uPC прыгнуть на адрес 0000)
1_0000_1_011_0
```

1. **Реализация Micro-ROM:** Управляющий автомат считывает сигналы из массива памяти, а не использует жесткую логику `always @(*)` и `case`.
