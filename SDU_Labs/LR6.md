## 2. Краткий экскурс в Verilog для регистров

Регистры строятся на D-триггерах, которые уже были рассмотрены в `Лабораторной работе №4` и `Лабораторной работе №5`. Напомним ключевые конструкции.

### 2.1. D-триггер как базовый элемент

```verilog
module d_ff (
    input wire clk,
    input wire rst,
    input wire d,
    output reg q
);
    always @(posedge clk or posedge rst) begin
        if (rst) q <= 1'b0;
        else q <= d;
    end
endmodule
```

### 2.2. Многоразрядные сигналы (векторы)

В Verilog для описания шин данных используются векторы: `reg [3:0] data` – 4-битный регистр. Индексация: `data[0]` – младший бит, `data[3]` – старший.

### 2.3. Параметризация

Для создания регистров на произвольное число разрядов используется `parameter`:

```verilog
module register #(parameter WIDTH = 4) (
    input wire clk, rst,
    input wire [WIDTH-1:0] d,
    output reg [WIDTH-1:0] q
);
    always @(posedge clk or posedge rst)
        if (rst) q <= {WIDTH{1'b0}};
        else q <= d;
endmodule
```

### 2.4. Сдвиговые операции

- `q >> 1` – сдвиг вправо (младший бит теряется, старший становится 0)
- `q << 1` – сдвиг влево
- `{din, q[WIDTH-1:1]}` – конкатенация для сдвига вправо с последовательным входом
- `{q[WIDTH-2:0], din}` – сдвиг влево с последовательным входом

### 2.5. Установка инструментов

Инструкции по установке Icarus Verilog и GTKWave даны в ЛР3. Кратко:

- **Ubuntu:** `sudo apt install iverilog gtkwave`
- **Windows:** [bleyer.org/icarus](https://bleyer.org/icarus/), при установке добавить в PATH.

Проверка: `iverilog -V` и `gtkwave --version`.

## 3. Теоретическая часть

**Регистром** называется устройство, предназначенное для приема, кратковременного хранения и выдачи кодов слова, а также выполняющее логические преобразования над кодом слова. 
Регистр представляет собой совокупность триггеров и вспомогательных логических схем, количество и схема соединений которых зависит от количества разрядов в коде и набора операций, выполняемых регистром.

Помимо хранения кода слова регистры, в общем случае, обеспечивают выполнение следующих операций:
- установка регистра в нулевое состояние «сброс»;
- прием кода слова из другого устройства;
- передача кода слова в другое устройство;
- преобразование кода числа: преобразование прямого кода в обратный
код и наоборот;
- преобразование последовательного кода слова в параллельный код и
наоборот;
- сдвиг кода слова вправо или влево на требуемое число разрядов.

Регистры, как правило, строятся на D-триггерах, т.к. эти триггеры позволяют производить запись информации однофазным кодом без предварительного "обнуления" по входу D.
Приём информации в регистр и выдача может осуществляться параллельно и последовательно. В первом случае слово представляется в виде параллельного кода. При записи и при считывании все разряды кода слова передаются одновременно, каждый разряд по своей кодовой шине. При последовательной передаче кода слова, все разряды кода слова передаются последовательно во времени один за другим и строго в определенные дискретные моменты времени, совпадающие с управляющими сигналами.

Различают, сдвигающие регистры, в которых возможен сдвиг хранимого кода и регистры без сдвига с приемом информации параллельным кодом.


### 3.1. Классификация регистров

| Тип | Описание |
|-----|----------|
| **Параллельный регистр** | Загрузка и выдача всех разрядов одновременно (параллельный код). |
| **Сдвиговый регистр** | Информация сдвигается на один разряд за такт; может преобразовывать последовательный код в параллельный и наоборот. |
| **Реверсивный сдвиговый регистр** | Направление сдвига (влево/вправо) переключается управляющим сигналом. |
| **Универсальный регистр** | Поддерживает несколько режимов: параллельная загрузка, сдвиг влево, сдвиг вправо, хранение, обнуление. Выбор режима осуществляется через управляющие входы. |

### 3.2. Регистр параллельной загрузки

Схема – набор D-триггеров с общей шиной тактового сигнала и сброса. Выходы могут быть поданы через элементы «И-НЕ» для выдачи в прямом или инверсном коде.

### 3.3. Сдвиговый регистр (последовательный вход – параллельный выход)

Состоит из цепочки D-триггеров, где выход каждого подключен к входу D следующего. Вход первого триггера – последовательные данные. Через n тактов на выходах всех триггеров оказывается параллельный код.

### 3.4. Сдвиговый регистр (параллельный вход – последовательный выход)

Параллельные данные загружаются в триггеры, затем под действием тактов сдвигаются к выходу последнего триггера.

### 3.5. Реверсивный сдвиговый регистр

Имеет вход направления `dir`: при `dir=1` – сдвиг влево (к старшим разрядам), при `dir=0` – сдвиг вправо (к младшим). Переключение путей осуществляется мультиплексорами.

### 3.6. Универсальный регистр

Обычно имеет два управляющих входа `mode[1:0]`:

| mode | Режим |
|------|-------|
| 00   | Хранение |
| 01   | Сдвиг вправо |
| 10   | Сдвиг влево |
| 11   | Параллельная загрузка |

## 4. Verilog-модели и тестовые стенды

### 4.1. Параметризуемый D-триггер (субблок)

`d_ff.v` – базовый элемент.

```verilog
module d_ff (
    input wire clk,
    input wire rst,
    input wire d,
    output reg q
);
    always @(posedge clk or posedge rst) begin
        if (rst) q <= 1'b0;
        else q <= d;
    end
endmodule
```

### 4.2. Регистр параллельной загрузки (N-разрядный)

**Модуль `par_register.v`:**

```verilog
module par_register #(parameter WIDTH = 4) (
    input wire clk,
    input wire rst,
    input wire [WIDTH-1:0] d,
    output reg [WIDTH-1:0] q
);
    always @(posedge clk or posedge rst) begin
        if (rst) q <= {WIDTH{1'b0}};
        else q <= d;
    end
endmodule
```

*Примечание:* Для считывания в прямом и обратном коде можно добавить выходы `q_inv = ~q`, но обычно это делается на уровне тестбенча или внешней логики.

**Testbench `par_register_tb.v`:**

```verilog
`timescale 1ns / 1ps
module par_register_tb();
    reg clk, rst;
    reg [3:0] d;
    wire [3:0] q;
    
    par_register #(.WIDTH(4)) dut (clk, rst, d, q);
    
    always #5 clk = ~clk;
    
    initial begin
        $dumpfile("par_register.vcd");
        $dumpvars(0, par_register_tb);
        clk = 0; rst = 1; d = 0;
        #15 rst = 0;
        #10 d = 4'b1010;
        #10 d = 4'b0101;
        #10 d = 4'b1111;
        #20 $finish;
    end
endmodule
```

### 4.3. Сдвиговый регистр (последовательный вход – параллельный выход)

**Модуль `sipo_register.v` (Serial-In Parallel-Out):**

```verilog
module sipo_register #(parameter WIDTH = 4) (
    input wire clk,
    input wire rst,
    input wire sin,          // последовательный вход
    output reg [WIDTH-1:0] q // параллельный выход
);
    always @(posedge clk or posedge rst) begin
        if (rst) q <= {WIDTH{1'b0}};
        else q <= {q[WIDTH-2:0], sin};  // сдвиг влево (младший бит на вход)
    end
endmodule
```

**Testbench `sipo_tb.v`:**

```verilog
`timescale 1ns / 1ps
module sipo_tb();
    reg clk, rst, sin;
    wire [3:0] q;
    
    sipo_register #(.WIDTH(4)) dut (clk, rst, sin, q);
    
    always #5 clk = ~clk;
    
    initial begin
        $dumpfile("sipo.vcd");
        $dumpvars(0, sipo_tb);
        clk = 0; rst = 1; sin = 0;
        #15 rst = 0;
        // Подаём последовательно 1,0,1,1 (старший бит первым)
        #10 sin = 1;  // 1-й такт
        #10 sin = 0;  // 2-й
        #10 sin = 1;  // 3-й
        #10 sin = 1;  // 4-й
        #20 $finish;
    end
endmodule
```

### 4.4. Сдвиговый регистр (параллельный вход – последовательный выход)

**Модуль `piso_register.v` (Parallel-In Serial-Out):**

```verilog
module piso_register #(parameter WIDTH = 4) (
    input wire clk,
    input wire rst,
    input wire load,         // сигнал параллельной загрузки (активный высокий)
    input wire [WIDTH-1:0] d,
    output reg sout          // последовательный выход
);
    reg [WIDTH-1:0] shift_reg;
    
    always @(posedge clk or posedge rst) begin
        if (rst) begin
            shift_reg <= {WIDTH{1'b0}};
            sout <= 1'b0;
        end else if (load) begin
            shift_reg <= d;
            sout <= d[WIDTH-1];   // первый бит сразу на выход
        end else begin
            shift_reg <= {shift_reg[WIDTH-2:0], 1'b0};
            sout <= shift_reg[WIDTH-2];
        end
    end
endmodule
```

**Testbench `piso_tb.v`:**

```verilog
`timescale 1ns / 1ps
module piso_tb();
    reg clk, rst, load;
    reg [3:0] d;
    wire sout;
    
    piso_register #(.WIDTH(4)) dut (clk, rst, load, d, sout);
    
    always #5 clk = ~clk;
    
    initial begin
        $dumpfile("piso.vcd");
        $dumpvars(0, piso_tb);
        clk = 0; rst = 1; load = 0; d = 0;
        #15 rst = 0;
        // Загрузка параллельного кода 1010
        #10 d = 4'b1010; load = 1;
        #10 load = 0;
        // Сдвиг: на sout должны выйти 1,0,1,0 последовательно
        #40 $finish;
    end
endmodule
```

### 4.5. Реверсивный сдвиговый регистр

**Модуль `bidir_shift_register.v`:**

```verilog
module bidir_shift_register #(parameter WIDTH = 4) (
    input wire clk,
    input wire rst,
    input wire dir,          // 1 - сдвиг влево, 0 - сдвиг вправо
    input wire sin_left,     // вход для сдвига влево (младший бит)
    input wire sin_right,    // вход для сдвига вправо (старший бит)
    output reg [WIDTH-1:0] q
);
    always @(posedge clk or posedge rst) begin
        if (rst) q <= {WIDTH{1'b0}};
        else begin
            if (dir)  // сдвиг влево
                q <= {q[WIDTH-2:0], sin_left};
            else      // сдвиг вправо
                q <= {sin_right, q[WIDTH-1:1]};
        end
    end
endmodule
```

**Testbench `bidir_tb.v` (фрагмент):**

```verilog
initial begin
    // ... после сброса
    dir = 1; sin_left = 1;  // задвигаем единицу влево
    #10 sin_left = 0;
    #10 sin_left = 1;
    #10 dir = 0; sin_right = 1; // сдвиг вправо
    #10 sin_right = 0;
    #20 $finish;
end
```

### 4.6. Универсальный регистр (4 режима)

**Модуль `universal_register.v`:**

```verilog
module universal_register #(parameter WIDTH = 4) (
    input wire clk,
    input wire rst,
    input wire [1:0] mode,   // 00: hold, 01: shift right, 10: shift left, 11: load
    input wire [WIDTH-1:0] d_parallel,
    input wire sin_left, sin_right,
    output reg [WIDTH-1:0] q
);
    always @(posedge clk or posedge rst) begin
        if (rst) q <= {WIDTH{1'b0}};
        else begin
            case (mode)
                2'b00: ;  // хранение
                2'b01: q <= {sin_right, q[WIDTH-1:1]};   // сдвиг вправо
                2'b10: q <= {q[WIDTH-2:0], sin_left};    // сдвиг влево
                2'b11: q <= d_parallel;                  // параллельная загрузка
            endcase
        end
    end
endmodule
```

**Testbench `universal_tb.v`:**

```verilog
`timescale 1ns / 1ps
module universal_tb();
    reg clk, rst;
    reg [1:0] mode;
    reg [3:0] d_parallel;
    reg sin_left, sin_right;
    wire [3:0] q;
    
    universal_register #(.WIDTH(4)) dut (clk, rst, mode, d_parallel, sin_left, sin_right, q);
    
    always #5 clk = ~clk;
    
    initial begin
        $dumpfile("universal.vcd");
        $dumpvars(0, universal_tb);
        clk = 0; rst = 1; mode = 0; d_parallel = 0; sin_left = 0; sin_right = 0;
        #15 rst = 0;
        // 1. Параллельная загрузка 1010
        mode = 2'b11; d_parallel = 4'b1010; #10;
        mode = 2'b00; #10;  // хранение
        // 2. Сдвиг вправо, подаём 1
        mode = 2'b01; sin_right = 1; #10;
        sin_right = 0; #10;
        // 3. Сдвиг влево, подаём 0
        mode = 2'b10; sin_left = 0; #10;
        sin_left = 1; #10;
        // 4. Снова параллельная загрузка
        mode = 2'b11; d_parallel = 4'b1111; #10;
        mode = 2'b00; #20;
        $finish;
    end
endmodule
```
